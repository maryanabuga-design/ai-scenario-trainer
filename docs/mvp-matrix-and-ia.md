# MVP scope and information architecture

Source: the FigJam board sections "Матриця MVP" (feature matrix) and "Інформаційна архітектура MVP" (information architecture). If this file and the board disagree, the board wins. Ask the user before changing scope.

## MVP criterion
One complete learning cycle: upload material → configure the session → answer scenario or quiz questions → see the result and the answers with sources → return to weak topics.
If the cycle cannot work without a feature, it is Must.

## Information architecture
Assumption to confirm with the user: four sections live in the bottom navigation (Home, Materials, Progress, Profile). Onboarding, Scenario session and Session results are opened from other screens and have no navigation item.

- Onboarding (Онбординг): Practise a decision · Explain it, then check it · See what to repeat · Ready to start? (replayed from "How the app works" in Profile)
- Home (Головна): avatar, greeting and notification bell · status sentence · hero card Training materials (Choose a topic to Training) · tiles: Exam, Steps, Weak topics, Saved questions · Mini-quiz row
- Materials (Матеріали): grouped list of the guide topics (S1 to S10, F1 to F7) · reading screen of a topic (no bottom navigation) · at its end Practise this topic (a practice session of the topic, started or resumed directly), Steps for this topic (the Steps topic screen); moving between topics only with the header arrows. The earlier tabs, upload sheet and material page are no longer reachable from the tab
- Progress (Прогрес): Summary · Result by session · Guide sections · Session history. Rule: Home = what to do now (continue or start, tiles, Mini-quiz); Progress = how you are doing over time, with no duplicated actions (it only links to the Weak topics page)
- Profile (Профіль): Direction · Settings · Help: How the app works (opens onboarding)
- Notifications (Сповіщення): bell on Home → New / Earlier list · tap marks as read and opens the target · Mark all as read · empty state (demo data, no backend or push)
- Saved questions (Збережені): Saved list · single saved question · Repeat saved (from the Saved tile on Home)
- Steps (Кроки): Home tile → list of topics → informational topic screen with accordion steps (no completion tracking) · Reading → Steps for this topic → topic screen
- Mini-quiz (Міні-квіз): topics · 5, 10 or 15 questions · start (from Training and Home)
- Exam (Іспит): exam screen (readiness, deadline, rules, last and best result) · timed question session · results and answer review (from the Exam tile on Home)
- Training (Тренування): stats · Scenario/Quiz switch · Mini-quiz card (Quiz mode) · topic cards with parts (a part starts at once) · one question screen with the step strip and Next or Finish · Exit confirmation · Source sheet (Should). There is no feedback, confidence, explanation or Ask AI during the session
- Session results (Результати сесії): Results (hero, Passed or Not passed yet, percentage and pass mark, conclusion, Weak topics card, Review answers and Repeat weak topics) · Weak topics · Answer review (one per question, with Ask AI about this step for scenario steps) · Repeat round

## Main flow (the learning cycle)
Home → Training (choose a part) → Question (choose an option) → Next, for every question (Back and the step strip move between questions and keep the answers) → Finish.
- Finish: Results (Passed or Not passed yet, percentage, Weak topics) → (A) Weak topics → choose topics → Repeat selected → a repeat round of the questions answered wrong → Results; (B) Review answers → Answer review from the first question (a strip marks right and wrong; all options, the correct one, your choice, Why, Guide chips; Previous and Next) → Back to results. Progress is saved after each session.

## Build notes
- No live AI calls. Every AI behaviour is simulated from the prepared scenario. The footer note "AI behavior is simulated for this prototype" is shown on Profile only (and in the README under known limitations); session screens never mention AI or a bot.
- Mobile-first, following DESIGN.md.
- Keep to the Must and Should features. Do not build the Could and Won't features.
